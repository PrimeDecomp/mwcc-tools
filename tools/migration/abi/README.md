# Rust producer ABI spike

`local_call.rs` translates only the `lc.call` wrapper (`fn_00460c90`) from `src/oracle/Hooks.c`. It uses a raw pointer to a packed prefix of `IROLinear`, the unsigned-byte `Boolean` return convention, and the retained C `OracleTrace_Printf` varargs shim. It introduces no Rust allocator, unwinding or runtime imports.

This is a feasibility experiment, not the default producer. Other hooks and the output shim remain C. Passing it does not establish the layouts of the other compiler structures or complete migration stage 6.

The current integrated opt-in build now uses a separate Rust output object as well as the hook object; the original experiment and its frozen evidence still use the C shim. The Rust writer exports the two legacy output APIs and calls the original compiler's stdio. Separating its object from Rust variadic callers keeps those argument lists opaque to LLVM. `trace_layout.c`, `trace_runtime.c` and `trace_caller.rs` provide seven FILE/ABI probes and 24 fresh-process differential scenarios per version, including raw mixed C/Rust varargs, errors, caching and reentrant callbacks. `verify_trace_writer.py` runs that harness; use the supported private loader on Linux. `verify_trace_files.py` separately checks real append/stderr behavior with the original runtime. See the integrated producer guide for build/lint commands and ownership checks.

The integrated implementation has moved to [`mwcc-oracle-hooks`](../../../crates/mwcc-oracle-hooks/README.md), which also ports graph simplification, selection and frame layout. The standalone file remains the original bounded spike; new oracle builds can opt into the integrated group with `--rust-hooks`. The frame extension adds a 33-value C layout probe and three direct runtime scenarios, bringing the integrated harness to twelve cases per version. Frame trace parity is checked without normalization; object/diagnostic equivalence and graph checks remain required.

The subsequent PCode/scheduler group adds two retail wrappers and three shared exports used by the remaining C callers. Its 76-value layout probe and eighteen C/Rust differential scenarios bring the integrated harness to thirty cases per version. The reference helper bodies are extracted from the frozen C checkout, hashed and compiled unchanged apart from symbol aliases; both implementations observe the same live records, so the harness compares exact format/argument bytes rather than normalized identities. See `pcode_layout.c`, `pcode_runtime.c` and the integrated producer guide for the current boundary.

The integrated harness now checks 376 cases per version after the block/stage, scalar/CSE, ancestry and common instantiation groups. `instantiation_layout.c` and `instantiation_runtime.c` add fourteen layout/width probes and 96 differential scenarios for six template/body observers. The hook object owns 25 retail wrappers and nine helpers, separate from the Rust output object. Version-specific inline decisions, expression expansion and deferred-node dispatch, plus argument bindings, remain to migrate. `verify_link.py --compiled-oracle-root DIR` uses the current native C/Rust objects when comparing the two linkers; this also permits comparison with the actual native executable rather than a link using older retained C bodies.

The binding observer extends the current object to 26 wrappers/nine helpers and the harness to 448 cases per version. `bindings_layout.c` checks 44 sizes, offsets, widths and enum values; `bindings_runtime.c` adds 72 differential scenarios, including all binding modes, nullable metadata, signed formal counts, name identity, odd-address records, expression unwrapping and state changed by retail. The first prototype returned the raw generated-function bit rather than C's logical result; scenario 39 caught that mismatch before integration. The corrected observer preserves the exact Boolean value in the trace.

The separate frontend object now supplies the remaining five wrappers, bringing Rust mode to all 31 configured hooks without compiling C observation sources. `frontend_layout.c` measures 61 header layout/width/enum values; `frontend_runtime.c` runs 256 frozen-C/Rust differential scenarios for each compiler version, including nested/full costs and the version-specific option/body accesses. `verify_frontend.py` builds and validates each frontend object independently. The common 448-case harness remains separate, and all three objects are exercised together through native builds and complete trace comparisons. The standalone local-call experiment above remains historical evidence.

The block/stage group adds three wrappers, an eighteen-value layout/flag probe and forty-two differential scenarios, for seventy-two ABI cases per version. `blocks_reference.h` is extracted from the frozen C source at verification time. The cases cover every merge explanation and its priority, environment-query/retail-call order, changing options and block state, nullable inputs, signed fields and unsigned-byte arguments. See `blocks_layout.c` and `blocks_runtime.c`.

The scalarization/CSE group adds seven wrappers and two shared exports, including expression spelling, propagation and optimizer dump forwarding. Its 92-value probe and 88 differential scenarios bring the harness to 160 cases per version. `scalar_cse_reference.h` is extracted and hashed from the frozen C bodies. The runtime compares original caller addresses, signed scalar fields, CSE pass state, options changed between queries, dump-file activation and raw mixed variadic arguments. See `scalar_cse_layout.c` and `scalar_cse_runtime.c`; the integrated producer guide documents the x86 entry stubs, runtime-import boundary and diagnostics options.

The allocation/origin group adds three wrappers and four shared exports, a 104-value probe and 120 differential cases, for 280 runtime cases per version. `origins_reference.h` contains the frozen C table/walker/context/allocation bodies. Cases cover every traversed ENode family, collision wraparound, the 49,152-entry admission boundary, updates and capacity rejection, depth/chain bounds, parent/link capture before retail, statements changed by retail, nullable/sentinel returns, nested source-line restoration, and allocation reset/snapshot order. The table is twelve-byte records packed to two-byte alignment. The only additional C library import is the existing `memset` export used for reset. See `origins_layout.c` and `origins_runtime.c`.

Results on 2026-10-16: the object links through both orchestrators on GC 1.3, 1.3.2 and 2.7 on Windows and Linux/wibo; C probes report `[Boolean=1, pointer=4, IROLinear=56, index=8, flags=2]` for each. On Windows, each linked Rust-hook oracle passes 2,313/2,313 canaries with all optional trace families. A separate C entry-point harness passes seven direct cases on each version on both hosts: disabled/null/empty settings, enabled tracing, packed reads of an index above 32767, byte returns including 128/255, and the C varargs format/value. Its only Windows import is ExitProcess. Local results are retained in `build/rust-migration/abi/results.json`, `runtime-results.json` and `runtime-results-linux.json`.

**Decision:** the simple-hook ABI is feasible. Continue porting hook groups incrementally with per-structure layout and trace-content checks. This evidence does not justify switching all hooks to Rust yet or treating the remaining C code as an infeasible exception.

From the repository root on Windows:

```powershell
rustup target add i686-pc-windows-msvc
rustc --edition 2024 --target i686-pc-windows-msvc --crate-type lib --emit=obj -C panic=abort -C opt-level=2 -C debuginfo=0 -C codegen-units=1 tools/migration/abi/local_call.rs -o build/rust-migration/abi/local_call.obj
uv run --python 3.13 --no-project python tools/migration/verify_link.py --binary target/release/mwcc-tools.exe --oracle-root F:/tmp/mwcc-oracle --oracle --rust-hook build/rust-migration/abi/local_call.obj --canaries F:/tmp/mwcc-rs/canaries --keep build/rust-migration/abi/results.json
```

Create the output directory before invoking rustc. The pinned Rust toolchain emits ordinary i386 COFF. The verifier checks its external symbols, suppresses the corresponding C definition only in isolated copies, and supplies the Rust object through the existing `oracle/compiled` boundary. It compares Python/native historical-linker orchestration, compiles a C layout probe using each version's source compiler, and can run the complete canary corpus with all optional traces. Results are saved only after the corresponding checks pass. The reference installation is read without modification.

The object must define `_fn_00460c90` and import exactly `_fn_00460c90__retail`, `_getenv` and `_OracleTrace_Printf`. C layout probes must establish a one-byte Boolean, four-byte pointer and `IROLinear` index/flags offsets of 8/2 on all three versions. A complete hook conversion still needs equivalent checks for every accessed structure, union, bitfield and version-specific layout, plus trace-content and corpus parity with tracing disabled and enabled. The harness source is `runtime.c`; the independent original compiler also receives its adjacent license DLL before corpus execution.
