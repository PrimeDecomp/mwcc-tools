# The engine's methods

`mwcc-tools` runs the oracle's tools as **methods**: named operations with JSON parameters and results, in a
**session** that keeps what it loads. The same methods answer three ways:

- `mwcc-tools serve [--project DIR] [--oracle-root DIR]`: a session over JSON lines on standard input and output.
  Requests run at once, each on a thread of its own. The session keeps projects, units, their targets, compiled
  objects (the compile cache) and loaded traces until the input ends.
- `mwcc-tools call METHOD [@PARAMS.json | KEY=VALUE ...] [--project DIR] [--oracle-root DIR]`: one method in a
  fresh session, its results one JSON object per line. A VALUE that is JSON is read as JSON, any other as text; a
  KEY may be dotted (`files.src/a.cpp=...`, `a.unit=main/Foo`).
- The Python package `mwcc_tools` (python/README.md): `Engine` runs `serve`; `Unit` and `Trace` wrap the unit and
  trace methods.

`mwcc-tools methods` lists the methods; `mwcc-tools methods NAME` gives one's parameter and result schemas (JSON
Schema 2020-12). The reference below is generated from those schemas.

## The protocol

A request is one line: `{"id": ID, "method": NAME, "params": {...}}`. ID is any JSON value the caller chooses. The
server answers on standard output, one line each:

```
{"id": ID, "result": {...}}                      one or more: the method's results, as they are made
{"id": ID, "done": true, "timing": {...}}        the end, with where the time went
{"id": ID, "error": {"message": "..."}}          or the end, failed
```

A method gives one result, except where its reference says it streams (`experiment.run` gives a row per
candidate as it finishes, then its summary). A result that is not an object is given as `{"value": ...}`.

`{"id": ID2, "method": "cancel", "params": {"id": ID}}` stops the request ID: a compile in progress stops, an
experiment writes what it finished and ends, a source-guided run finds its cancel file. Its answer says whether
ID was running (`{"cancelled": true}`).

**Lists:** any method takes `inputs`, a list of parameter objects, each merged over the other parameters. The
method then runs once per input, in order, and gives one result per input with its `index`; an input's failure
is that result's `error`, not the call's. (`methods.list` with `inputs: [{"name": "unit.score"}, ...]`.)

**Timing:** each result carries `timing`, in milliseconds by stage: `load` (projects, units, targets), `compile`,
`score`, `trace` (traced compiles), `model` (colouring models), `queue` (waiting for a thread) and `other`.

**Versions:** `session.hello` gives `schema_version` (this document's: 1), the build's `version` and the
methods. A change that breaks a caller bumps the schema version; the Python package refuses a server of another
one.

## Sessions and handles

A **project** is a decomp project's directory: its objdiff.json, build.ninja and, once built, report.json. A
method names it by `project` (absolute, or from the server's directory), else the session's `--project`.

A **unit** is named by `unit` (objdiff.json's name, e.g. `main/MetroidPrime/CControlMapper`) with `project`, or
by the `handle` `unit.load` gave. The session loads a unit once: its flags, compiler, target object and the
target's symbols stay loaded.

**Files** (`files`) replace the disk's for a compile: `{"src/Foo.cpp": "text", "include/Bar.hpp": null}`, paths
from the project's directory, `null` for a file that should be absent. Nothing is written to the tree; the
compiler reads the overlay in place of the disk.

A **trace** is named by the handle `trace.load` gave (`trace:N`): a unit's traced compile, or a saved trace.

**Text:** the methods that replace a command that printed a report take `text: true` and give its lines as
`text`, the same lines the command printed.
